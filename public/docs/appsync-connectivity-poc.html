AWS AppSync Events 실제 통신 1차 PoC

Vue2 사업자 화면에서 발행한 이벤트가 AWS AppSync Events를 거쳐 Next.js 단말 화면까지 실제로 도착하는지 가장 작은 범위로 검증한다. 사업자 1:N 연결과 운영 보안은 통신 성공을 확인한 다음 단계에서 적용한다.

목표와 범위상세 아키텍처호출 순서통신 규격테스트 방법확인 범위백로그

1. 테스트 목표와 범위

이번 단계의 성공 조건

Next.js 화면에 채널 구독 완료가 표시된 상태에서 Vue2 버튼을 누르면 Next.js UI가 대기 화면에서 메인 화면으로 전환되어야 한다.

이번 테스트에 포함

  • Vue2 브라우저에서 테스트 버튼을 제공한다.
  • Vue2 브라우저가 AppSync HTTP endpoint를 직접 호출한다.
  • 테스트 API Key로 이벤트를 발행한다.
  • 고정 채널 /default/test를 사용한다.
  • Next.js 브라우저가 Amplify Events SDK로 AppSync에 연결한다.
  • Next.js 브라우저가 고정 채널을 구독한다.
  • display.changed 이벤트를 수신한다.
  • 대기 화면을 메인 화면으로 전환한다.

이번 테스트에서 제외

  • deviceSerialNo를 읽거나 검증하지 않는다.
  • merchantCode를 조회하거나 검증하지 않는다.
  • Vue2 로그인 세션을 검증하지 않는다.
  • 사업자별 1:N 채널을 구성하지 않는다.
  • 특정 단말 타겟팅을 적용하지 않는다.
  • Next.js 서버 publish API를 사용하지 않는다.
  • 자동 재연결을 구현하지 않는다.
  • ACK와 이벤트 복구를 구현하지 않는다.

2. 현재 1차 PoC 상세 아키텍처

Vue2의 역할

  • 사용자의 버튼 클릭을 받는다.
  • 이벤트 payload를 만든다.
  • AppSync HTTP endpoint로 발행한다.
  • HTTP 성공 또는 실패를 표시한다.

AppSync의 역할

  • WebSocket 연결을 수락한다.
  • 채널 구독을 등록한다.
  • HTTP 이벤트를 수신한다.
  • 동일 채널 구독자에게 전달한다.

Next.js의 역할

  • Amplify를 endpoint와 region으로 설정한다.
  • events.connect()로 고정 채널에 연결한다.
  • channel.subscribe()로 이벤트를 받는다.
  • 대기 UI를 메인 UI로 바꾼다.

3. 실행 시 실제 호출 순서

  1. Next.js 환경변수 검사HTTP endpoint와 region과 API Key가 존재하는지 확인한다. 예시 placeholder가 남아 있으면 Amplify를 설정하지 않고 오류를 표시한다.
  2. Amplify 설정Next.js가 Amplify.configure()에 HTTP endpoint와 region과 API Key를 전달한다.
  3. 채널 연결 요청Next.js가 events.connect('/default/test')를 호출한다. SDK가 Realtime endpoint와 WebSocket 인증 정보를 구성한다.
  4. 이벤트 구독 등록Next.js가 channel.subscribe()를 호출한다. SDK가 connection_init과 subscribe protocol 메시지를 처리한다.
  5. 구독 승인 대기Next.js가 subscription의 ready Promise를 기다린다.
  6. 채널 구독 완료ready가 완료되면 화면에 “연결됨”을 표시한다.
  7. Vue2 이벤트 생성사용자가 Vue2 테스트 버튼을 누르면 display.changed 이벤트를 JSON 문자열로 만든다.
  8. Vue2 HTTP publishVue2가 AppSync HTTP endpoint에 API Key와 채널과 events[]를 담아 POST한다.
  9. AppSync 채널 라우팅AppSync가 발행 요청의 채널과 동일한 채널을 구독 중인 WebSocket 세션을 찾는다.
  10. Next.js 이벤트 수신AppSync가 data 메시지를 보내면 Next.js가 data.event 배열의 각 JSON 문자열을 파싱한다.
  11. UI 전환이벤트 type이 display.changed이고 현재 화면이 WAITING일 때만 MAIN으로 바꾼다.
  12. 연결 정리컴포넌트가 종료되면 Next.js가 unsubscribe를 전송하고 WebSocket을 닫는다.

Amplify.configure({
  API: {
    Events: {
      endpoint: "https://{api-id}.appsync-api.us-east-1.amazonaws.com/event",

      defaultAuthMode: "apiKey",
      apiKey: "{test-api-key}"

  }

const channel = await events.connect("/default/test");
const subscription = channel.subscribe({ next, error });
await subscription.ready;

5. 환경변수와 테스트 방법

Next.js .env.local

NEXT_PUBLIC_APPSYNC_HTTP_URL=https://{api-id}.appsync-api.us-east-1.amazonaws.com/event
NEXT_PUBLIC_APPSYNC_REGION=us-east-1
NEXT_PUBLIC_APPSYNC_API_KEY=da2-...
NEXT_PUBLIC_APPSYNC_CHANNEL=/default/test
Endpoint 입력 규칙
  • AWS 콘솔에 표시된 HTTP endpoint 전체 주소를 한 줄로 입력한다.
  • 주소는 https://로 시작해야 한다.
  • 주소는 /event로 끝나야 한다.
  • endpoint의 AWS region과 설정 region을 일치시킨다.
  • <api-id> 같은 예시 문자열을 실제 값으로 교체한다.

Vue2 manager 환경변수

APPSYNC_HTTP_URL=https://{api-id}.appsync-api.us-east-1.amazonaws.com/event
APPSYNC_API_KEY=da2-...
APPSYNC_CHANNEL=/default/test

수동 테스트 절차

  1. AppSync 리소스 확인API Key가 publish와 subscribe를 허용하는지 확인한다.
  2. 동일 채널 확인Next.js와 Vue2의 채널 값이 모두 /default/test인지 확인한다.
  3. 두 앱 재시작환경변수 변경 후 개발 서버를 다시 실행한다.
  4. 구독 완료 확인Next.js 대기 화면에 “구독 상태: 연결됨”이 표시될 때까지 기다린다.
  5. 이벤트 발행Vue2 테스트 화면에서 “결제 시작 이벤트 보내기” 버튼을 누른다.
  6. 발행 결과 확인Vue2 화면에 “이벤트 전송 완료”가 표시되는지 확인한다.
  7. 수신 결과 확인Next.js 화면이 “메인 페이지”로 바뀌는지 확인한다.
  8. 채널 격리 확인Vue2 채널만 다른 값으로 바꿨을 때 Next.js 화면이 바뀌지 않는지 확인한다.
테스트 API Key 주의
  • Next.js의 NEXT_PUBLIC_* 값은 브라우저 번들에 노출된다.
  • Vue2 빌드 환경변수도 브라우저에서 확인할 수 있다.
  • 운영 API Key를 사용하지 않는다.
  • 테스트 Key의 수명과 권한을 최소화한다.
  • 테스트 완료 후 Key를 폐기하거나 회전한다.

6. 이 테스트로 확인되는 것과 확인되지 않는 것

이 테스트로 확인되는 것

  • AppSync HTTP endpoint에 publish 요청을 보낼 수 있는지 확인한다.
  • AppSync Realtime endpoint에 WebSocket으로 연결할 수 있는지 확인한다.
  • API Key가 연결과 구독과 발행에 사용 가능한지 확인한다.
  • 고정 채널 구독이 성공하는지 확인한다.
  • 동일 채널의 HTTP 이벤트가 WebSocket 구독자에게 전달되는지 확인한다.
  • AppSync의 data.event 형식을 코드가 파싱할 수 있는지 확인한다.
  • 수신 이벤트로 Next.js UI를 전환할 수 있는지 확인한다.
  • Next.js 서버에 장기 연결을 보관하지 않고 통신할 수 있는지 확인한다.

이 테스트로 확인되지 않는 것

  • 로그인한 Vue2 사용자의 사업자를 확인하지 않는다.
  • 단말이 어떤 사업자에게 속하는지 확인하지 않는다.
  • 다른 사업자 채널에 대한 접근 차단을 확인하지 않는다.
  • 한 사업자의 여러 단말에 이벤트가 전달되는지 확인하지 않는다.
  • 특정 단말 한 대만 타겟팅할 수 있는지 확인하지 않는다.
  • 브라우저에 노출되지 않는 운영 인증 방식을 확인하지 않는다.
  • 연결이 끊긴 후 자동으로 복구되는지 확인하지 않는다.
  • 단말이 백그라운드일 때 이벤트를 처리하는지 확인하지 않는다.
  • 오프라인 동안 놓친 이벤트를 복구하는지 확인하지 않는다.
  • 이벤트의 정확히 한 번 전달을 보장하지 않는다.
  • 단말의 화면 전환 완료를 ACK로 확인하지 않는다.
  • 1,000대 이상 연결 시 용량과 비용을 확인하지 않는다.

7. 후속 작업 백로그

현재 통신 성공을 확인한 다음 아래 순서로 운영 구조에 가까워지도록 확장한다.

P0실제 AppSync 통신 검증 완료

  • 실제 AppSync HTTP endpoint를 두 프로젝트에 설정한다.
  • 실제 AWS region을 Next.js에 설정한다.
  • 실제 테스트 API Key를 두 프로젝트에 설정한다.
  • Vue2 publish 성공 응답을 기록한다.
  • Next.js subscription의 ready 완료를 확인한다.
  • Next.js UI 전환을 확인한다.
  • 잘못된 채널의 이벤트가 도착하지 않는지 확인한다.
  • 브라우저 CORS 오류가 없는지 확인한다.
  • 배포 환경의 CSP가 WebSocket과 HTTP endpoint를 허용하는지 확인한다.
  • 검증 완료 후 테스트 API Key를 회전한다.

P1사업자 1:N 채널 도입

  • Vue2 로그인 토큰 검증 API 계약을 확정한다.
  • 로그인 토큰에서 검증된 merchantCode를 얻는다.
  • deviceSerialNo → merchantCode 조회 API 계약을 확정한다.
  • 단말의 소유 사업자 코드를 조회한다.
  • 사업자 채널 이름 규칙을 확정한다.
  • 같은 사업자의 N개 단말이 같은 채널을 구독하도록 한다.
  • 다른 사업자의 채널 접근을 차단한다.

P1운영 publish 보안 적용

  • Vue2의 AppSync 직접 publish를 제거한다.
  • Vue2가 로그인 토큰으로 백엔드 notify API를 호출하도록 한다.
  • 백엔드가 요청 body의 merchantCode를 신뢰하지 않도록 한다.
  • 백엔드 실행 Role에 AppSync publish 권한을 부여한다.
  • 백엔드가 IAM SigV4로 AppSync에 publish하도록 한다.
  • Vue2 번들에서 AppSync API Key를 제거한다.

P1단말 구독 권한 적용

  • 공개 API Key를 운영 구독 인증으로 사용하지 않는다.
  • 단기 토큰 또는 Lambda authorizer 적용 방식을 확정한다.
  • 인증된 단말의 허용 채널 정보를 claim에 포함한다.
  • 요청 채널과 허용 채널이 같은지 검증한다.
  • 단말에는 subscribe 권한만 부여한다.
  • 단말의 publish 권한을 차단한다.

P2특정 단말 타겟팅

  • 사업자 전체 단말 채널 규격을 유지한다.
  • 특정 단말 채널 규격을 추가한다.
  • 대상 단말이 로그인 사업자 소유인지 서버에서 확인한다.
  • 사업자 전체 발행과 특정 단말 발행의 UI를 구분한다.

P2연결 안정성과 실단말 검증

  • Exponential backoff를 적용한다.
  • 재연결 시 random jitter를 적용한다.
  • AppSync keepalive timeout을 감시한다.
  • 재연결 후 채널을 다시 구독한다.
  • Wi-Fi와 LTE 전환을 시험한다.
  • 실제 WebView background 동작을 시험한다.
  • 단말 화면 on/off 동작을 시험한다.
  • 장시간 idle 상태를 시험한다.

P2운영 관측과 용량 검증

  • 연결 성공과 실패 로그를 수집한다.
  • 구독 성공과 실패 로그를 수집한다.
  • publish 성공과 실패 로그를 수집한다.
  • CloudWatch 지표와 알람을 구성한다.
  • 비정상 요청 rate limit을 구성한다.
  • 1,000대 이상 동시 연결을 시험한다.
  • 동시 재접속 부하를 시험한다.
  • 실제 connection minute과 event operation을 측정한다.
  • 측정 결과로 운영 비용을 다시 산정한다.

조건부요구사항 변경 시 추가

  • 화면 전환 완료 확인이 필요해지면 ACK를 설계한다.
  • 오프라인 이벤트 복구가 필요해지면 최신 상태 저장을 설계한다.
  • 모든 이벤트 순차 복구가 필요해지면 이벤트 로그를 설계한다.
  • 중복 수신의 영향이 커지면 eventId 기반 멱등 처리를 적용한다.
  • 이벤트 순서가 중요해지면 revision을 적용한다.

8. 단계별 최종 방향

현재 단계

  • 고정 채널 하나를 사용한다.
  • API Key로 직접 연결한다.
  • 실제 통신만 검증한다.

다음 단계

  • 사업자를 검증한다.
  • 단말 소속을 검증한다.
  • 사업자 1:N 채널을 적용한다.

운영 단계

  • 백엔드 IAM publish를 사용한다.
  • 단말별 구독 권한을 제한한다.
  • 재연결과 관측성을 적용한다.
