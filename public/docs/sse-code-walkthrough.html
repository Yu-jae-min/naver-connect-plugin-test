현재 저장소 코드 기준 · 2026-09-18

Vue2 버튼을 누르면
Next.js 화면은 어떻게 바뀔까?

브라우저 요청 → 서버 함수 → 서버 메모리 → 열린 응답 → React 화면까지, 실행 위치와 실제 코드 줄을 연결한 안내입니다.

정적 코드 분석 문서입니다. 아래 단계 탐색은 설명용이며 실제 API를 호출하거나 SSE에 접속하지 않습니다. 네 파일의 줄 번호는 문서 생성 시점 기준입니다.

단계별 따라가기전체 실행 순서헷갈리는 개념전체 코드
가장 먼저: Next.js 화면이 SSE에 연결되어 있어야 버튼 이벤트를 받을 수 있습니다. OPTIONS는 조건부입니다. 버튼 클릭 때 GET/start를 다시 실행하지 않습니다. POST 응답과 SSE 화면 변경의 도착 순서는 고정되지 않습니다.

                start(controller)
                ReadableStream 생성 과정에서 스트림 API가 호출

                  이벤트마다 호출하지 않는다.

                  events L13을 처음 만나면 함수 본문은 아직 실행하지 않는다.

                처음에는 events L16, 이후에는 hub L31

                cancel()

                  HTTP로 보낸다. 객체 자체를 JSON 전송하지 않는다.

  • 
            연결 전에 버튼을 누르면 이벤트는 저장되지 않습니다. 구독자가 없어도
            POST는 성공할 수 있습니다.
          
    • 
          
  • 
            새로고침하면 React event 상태는 초기화되고 새 SSE 연결을 생성합니다.
            과거 이벤트 복구는 없습니다.
          
    • 
          
  • 
            여러 화면이 연결되어 있으면 모두 같은 이벤트를 받습니다. 결제/단말별
            구분이 없습니다.
          
    • 
          
  • 
            서버 재시작 및 다중 인스턴스에서 메모리는 공유되지 않습니다. 같은
            런타임에서 요청과 연결을 처리하는 PoC 전제입니다.
          
    • 
          
  • 
            heartbeat, SSE id:, 재전송 이력, 수신 확인, 메시지 타입 검증은
            없습니다.
          
    • 
          
  • 
            한 send에서 예외가 발생하면 뒤의 전송과 정상 성공 응답 생성이 중단될
            수 있습니다. JSON.parse에도 예외 처리가 없습니다.
          
    • 
          
  • 
            receivedAt은 서버 생성 시각이고 UTC 문자열입니다. 화면의 ‘수신
            시각’이라는 라벨과 정확한 의미는 다릅니다.
          
    • 
          
  • 
            event가 생긴 뒤에는 대기 화면으로 돌아가는 코드가 없습니다. 연결
            오류가 나도 결제 표시 상태는 유지됩니다.

  •

    • 
          
  • 
            Content-Type은 SSE 해석, no-transform은 중간 변환 방지 의도입니다.
            헤더만으로 프록시의 버퍼링·유휴 타임아웃까지 모두 통제하지는
