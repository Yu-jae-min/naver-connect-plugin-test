참고 · 현재 구현의 전제와 한계

  • 연결 유지 방식: 하나의 HTTP 응답을 ReadableStream으로 열어두고 계속 write(enqueue)하는 표준 SSE 방식. 클라이언트→서버는 별도의 POST /api/connect/notify 요청(9단계와 무관한 채널)으로 트리거.
  • 서버 상태 저장 위치: lib/sseHub.ts의 클라이언트 목록은 globalThis에 저장 — 로컬 next dev 단일 프로세스에서는 핫리로드에도 유지되지만, Vercel 서버리스 환경에서는 인스턴스별로 분리되어 있어 그대로 동작하지 않음 (다른 인스턴스가 처리한 POST를 SSE 커넥션을 들고 있는 인스턴스가 못 볼 수 있음).
  • 재연결/누락 이벤트 처리: 현재 구현은 브라우저 EventSource의 기본 자동 재연결에만 의존하며, 연결이 끊긴 동안 발생한 이벤트를 다시 따라잡는 별도 로직은 없음 (이전 시도에서 revision 기반 catch-up을 추가했다가 최초 진입 시 과거 이벤트가 즉시 노출되는 버그가 발생해 되돌림).
  • CORS: /api/connect/notify는 OPTIONS 핸들러 + 모든 응답에 Access-Control-Allow-Origin: * 헤더를 명시적으로 부착해 크로스 오리진 호출을 허용.
